- **A caller of `unapprove.yml` that grants only `pull-requests: write` starts again.** The workflow's default was `contents: read`, which its one job does not use. GitHub refuses to start a caller in another repository whose job grants less than the called workflow's default, so the whole calling workflow failed at start-up, and with it every review it holds. The default is now empty. With 0.12.0 or 0.13.0, grant `contents: read` as well; the docs' example does. A test checks that no shared workflow's default asks for more than its jobs do.
