# 0001: Instruct through shared standards, enforce through git and CI

Status: accepted, 2026-11-22.

## Decision

Every rule that must hold is enforced by git hooks, CI and required statuses, which work
the same whatever tool wrote the change. Instructions reach agents only through the two
formats the tools share: `AGENTS.md` and Agent Skills (`SKILL.md` with `name` and
`description` only). Per-tool files are thin adapters that point at those sources and are
generated by `devloop sync`. Agent hooks may call `devloop` for fast feedback but are
never the gate.

## Why

Claude Code, Codex, Gemini CLI, Cursor and Copilot agree on `AGENTS.md` and Agent Skills
and differ on everything else: hook files, event names and blocking semantics. A rule
that lives only in instructions or in one tool's hooks is a suggestion that some tools
skip. Hand-kept copies per tool drift apart.

## How to apply

- A new rule that matters gets a CI or git-hook check; the `AGENTS.md` text explains it.
- Never write rules into a tool-specific file; put them in an `AGENTS.md` block or a skill
  and let `devloop sync` render them.
- `devloop doctor --check` runs in CI, so a rendered copy that differs from its source
  fails the build.
- Skills use only the portable frontmatter. A tool-specific extra needs its own decision.

## Scope

All of devloop and every project that adopts it.
